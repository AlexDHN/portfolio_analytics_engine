# Portfolio Analytics Engine

A Python-based personal portfolio management system designed to track, analyze, and evaluate the performance of a multi-account investment portfolio. The project supports heterogeneous account types (listed equities, regulated savings, employee savings plans) and computes both performance and risk metrics on a daily time series.

---

## Overview

Most retail portfolio trackers are limited to simple P&L calculations. This project goes further by modeling each position individually from its transaction history, applying corporate action adjustments (stock splits, fractional shares), computing inflation-adjusted returns, and deriving standard quantitative risk metrics — all from a clean, extensible object-oriented architecture.

The system integrates live market data (via `yfinance`) and macroeconomic series (Banque de France Webstat API) with a disk-based caching layer to minimize redundant network calls.

---

## Key Features

- **Multi-account portfolio modeling** — supports listed accounts (PEA, CTO), regulated savings (Livret A, LDDS), and employee savings plans (PEE)
- **FIFO position matching** — accurate cost-basis tracking across buys, sells, and corporate actions
- **Stock split adjustment** — automatic detection and retroactive adjustment of share counts and values
- **Fractional share handling** — allocation of rompus generated by splits
- **Performance metrics** — total return, annualized return, dividend yield, cumulative benefit per position and per date
- **Risk metrics** — volatility, annualized volatility, downside deviation, maximum drawdown, VaR, CVaR (Expected Shortfall)
- **Inflation adjustment** — real return computation using HICP series from the Banque de France API
- **Simulated timeline** — "what-if" projection treating sold positions as if they had been held
- **Parallel initialization** — `ThreadPoolExecutor`-based concurrent construction of investment objects for large portfolios
- **Disk caching** — time-aware cache invalidation for market data and macroeconomic series

```
portfolio_project/

│
├── core/

│   ├── investments/
│   │   ├── base.py             # Abstract Investment interface
│   │   ├── listed_v2.py        # Listed equities & ETFs (splits, FIFO, metrics)
│   │   └── fixed_rate.py       # Fixed-rate savings (interest accrual, intervals)
│   └── market_data/
│       └── manager.py          # Centralized market data fetching & caching
│
├── factories/
│   └── inflation_factory.py    # Singleton provider for InflationService
│
├── loaders/
│   ├── bdf_api.py              # Banque de France Webstat API client
│   ├── inflation_loader.py     # Inflation series loader
│   └── sg_pee.py               # SG PEE fund data loader
│
├── services/
│   ├── cache.py                # Disk cache with TTL invalidation
│   └── inflation_service.py    # Inflation data service (singleton)
│
├── utils/                      # Logging, fee functions, math utilities
│
├── analyse_portefeuille.ipynb  # Main analysis notebook
├── .env                        # API keys (not committed — see .env.example)
├── .env.example                # Template for environment variables
├── requirements.txt
└── README.md
```

### Design Patterns

| Pattern | Where | Purpose |
|---|---|---|
| Abstract Base Class | `Investment`, `InvestmentAccount` | Enforces interface across account/investment types |
| Singleton | `InflationService` | Prevents redundant API calls across investment instances |
| Factory | `inflation_factory.py` | Centralizes dependency wiring and configuration |
| Parallel execution | `ThreadPoolExecutor` in accounts | Reduces initialization time for multi-ticker portfolios |
| Cache with TTL | `services/cache.py` | Avoids redundant network calls; supports partial refresh |

## Input Data — Excel Structure

The system reads transaction data from `data/investment.xlsx`. The file contains two sheets.

---

### Sheet 1 — `transactions` (default sheet)

This is the main transaction log. It is read with a 3-level MultiIndex: `(account_type, ticker, date)`.

```python
pd.read_excel("data/investment.xlsx", index_col=[1, 2, 0], usecols=range(11))
```

| Column | Type | Required | Description |
|---|---|---|---|
| `account_type` | `str` | ✅ Index | Account category. Values: `PEA`, `CTO`, `PEE`, `LR` (Livret réglementé) |
| `ticker` | `str` | ✅ Index | Yahoo Finance ticker (e.g. `AI.PA`) for listed assets, or product name for savings (e.g. `Livret A`) |
| `date` | `date` | ✅ Index | Transaction date |
| `value` | `float` | ✅ | Transaction amount in € (positive = buy / deposit, negative = sell / withdrawal) |
| `count` | `float` | ✅ | Number of shares (listed accounts only; use `0` or leave blank for savings) |
| `broker_fees` | `float` | ⬜ | Brokerage fees in € (defaults to `0` if missing) |
| `other_fees` | `float` | ⬜ | Other fees in € — e.g. custody fees (defaults to `0` if missing) |
| `tax` | `float` | ⬜ | Tax paid on the transaction in € — e.g. PFU (defaults to `0` if missing) |
| `abondement` | `float` | ⬜ | Employer matching contribution in € (PEE only; defaults to `0`) |
| `indice` | `str` | ✅ | Reference benchmark ticker for this transaction (e.g. `^FCHI` for CAC 40) |
| `annual_fee_rate` | `float` | ⬜ | Annual management fee rate for ETFs (e.g. `0.002` for 0.20% TER). Applied daily as `rate / 252` |

**Account type routing:**

| `account_type` value | Investment class | Market data source |
|---|---|---|
| `PEA`, `CTO` | `ListedInvestment` | yfinance |
| `PEE` | `ListedInvestment` | SG29 Haussmann (Selenium scraping) |
| `LR` | `FixedRateInvestment` | Banque de France API (Livret A rate) |

---

### Sheet 2 — `rompu`

Tracks fractional shares (rompus) generated by stock splits — i.e. the cash value of the non-integer part of a split allocation that the broker pays out rather than delivering as shares.

```python
pd.read_excel("data/investment.xlsx", sheet_name='rompu', index_col=[1, 2, 0])
```

| Column | Type | Description |
|---|---|---|
| `account_type` | `str` | Index — same values as main sheet |
| `ticker` | `str` | Index — ticker of the split instrument |
| `date` | `date` | Index — date the fractional share was credited |
| `value` | `float` | Cash value of the fractional share received in € |

## Metrics Reference

**Performance**

| Metric | Description |
|---|---|
| `total_return` | Cumulative return per position: `(market_value + dividends + fractional_shares - fees - equity) / equity` |
| `annualized_return` | CAGR from purchase date to valuation date |
| `dividend_yield` | Cumulative dividends received as a fraction of equity invested |
| `benefit` | Absolute P&L in euros (market value + income - cost) |

**Risk**

| Metric | Description |
|---|---|
| `volatility` | Standard deviation of daily returns |
| `annualized_volatility` | `volatility × √252` |
| `max_drawdown` | Maximum peak-to-trough decline in cumulative returns |
| `VaR (95%)` | 5th percentile of daily return distribution |
| `CVaR (95%)` | Expected loss conditional on exceeding VaR threshold |
